name: private_skills__manage_project_links
description: Provision each project's link_from_lib.sh + link_from_lib.yaml, which symlink private_skills into its .claude/skills
---

## Layout

```text
private_skills/
├── .claude/skills/private_skills__manage_project_links/
│   ├── scripts/
│   │   ├── links_lib.sh         # links::clean/add/sync/gitignore/report/sync_from_yaml/provision
│   │   └── links_yaml.py        # link_from_lib.yaml -> SRC<TAB>NAME lines
│   └── templates/
│       ├── link_from_lib.sh     # the constant copied into every project
│       └── link_from_lib.yaml   # the scaffold, written only where there is no yaml
└── .operation/project_links/
    ├── _all.sh                  # provisions + runs every target in subscribers.txt
    └── subscribers.txt          # data, not a script: one target dir per line

<project>/.claude/skills/
├── link_from_lib.sh             # GENERATED — identical in every project, overwritten each run
├── link_from_lib.yaml           # OWNED BY THE PROJECT — written once, then never touched
└── .gitignore                   # generated block: ignores the links only
```

Ownership splits by what changes:

| side | owns | changes | regenerated by `_all.sh` |
|---|---|---|---|
| library | `templates/link_from_lib.sh`, `links_lib.sh` | rarely | — |
| project | `link_from_lib.yaml` — which skills it takes | often | **never** |

Run `_all.sh` and every target is ready. A change to the template reaches every project at once; no project's yaml is ever rewritten.

## link_from_lib.yaml

```yaml
roots:                                    # absolute .claude/skills dirs that hold skill dirs
  core: /abs/path/to/private_skills/core__unit_skills/.claude/skills
  ops: /abs/path/to/private_skills/.claude/skills

links:                                    # skill names to link, grouped by root
  core:
    - unit__coding__sh
    - unit__rule__make_concise
  ops:
    - private_skills__structure
```

Adding a root: name it in `roots`, use that name as a `links` key. A `links` key with no matching root, an empty group, or a relative root path is an error — `links_yaml.py` exits 1 and the target dir is left untouched.

A scaffolded file carries **`core` only** — the one root every project has — plus the seven default unit skills (the `links` list in `templates/link_from_lib.yaml`). `ops` above is an example of a second root, not part of the scaffold. An unused root is harmless: only a `links` group with no matching root is an error.

To change what a *new* project starts with, edit that list in `templates/link_from_lib.yaml`. Existing projects keep their own yaml — the scaffold only ever fills a gap, so a default added later does not reach them.

`links: {}` is valid: a project that takes nothing yet. The **key** must be present, though — a missing `links` (or `roots`) key is a typo, and reading it as "empty" would silently drop every link instead of failing.

## link_from_lib.sh — generated into every project

```bash
#!/bin/bash
set -euo pipefail

ROOT="${PRIVATE_SKILLS_ROOT:-/abs/path/to/private_skills}"

source "$ROOT/.claude/skills/private_skills__manage_project_links/scripts/links_lib.sh"

links::sync_from_yaml
```

This file is **not** maintained per project. `templates/link_from_lib.sh` is the source, and `_all.sh` renders it into each target on every run, substituting `@@ROOT@@`. So a fix belongs in the template — editing a project's copy is lost on the next run.

`links::sync_from_yaml` finds `link_from_lib.yaml` through `BASH_SOURCE[1]` — the script that called it — so the yaml's directory *is* the target dir. No path is passed, and one script still owns one `DST`.

That one call runs all three steps in order:

| step | effect |
|---|---|
| `links::sync` | clean `DST`, then link every name in the yaml. **Skipped** when the yaml lists nothing |
| `links::gitignore` | rewrite the generated block in `DST/.gitignore` |
| `links::report` | `ls -l "$DST"` |

It stops at the first failure and returns non-zero. Pass a yaml path as `$1` to override the default.

An empty `links:` is not an error and not a wipe: `links::sync` is skipped, so existing links stay put. Removing all of a project's links is done by deleting the script and yaml, not by emptying the list.

## _all.sh — provision, then run

Each line of `subscribers.txt` is a **target dir**, normally `<project>/.claude/skills`. For each one:

| step | effect |
|---|---|
| `links::provision` | render `link_from_lib.sh` from the template; write `link_from_lib.yaml` **only if absent** |
| `bash <target>/link_from_lib.sh` | link from that yaml, write `.gitignore`, report |

So `_all.sh` is the only command needed. Run it after adding a project, after editing a yaml, and after editing the template.

It writes files, so a typo'd path would drop them somewhere real. Two guards run before anything is written: the target must end in `/.claude/skills`, and the project dir above it must exist. A failure is reported, not skipped.

## Add a project

1. Add `<project>/.claude/skills` to `subscribers.txt`.
2. Run `_all.sh`. It creates the dir, the script, and an empty yaml.
3. Edit that yaml to name the skills the project takes, and run `_all.sh` again.

## Rename or remove a skill

1. Rename or remove it in `private_skills`.
2. `.operation/project_links/_all.sh` — runs every target. It fails on the now-missing name and prints the path it looked for.
3. `grep -rl "<old_name>" --include=link_from_lib.yaml /abs/path/to/projects/` — lists the yaml files that name it. The project roots are in `subscribers.txt`.
4. In each hit: rename the name, or delete the line. Then rerun `_all.sh`.

`links::sync` cleans before it links, so orphans in `DST` self-heal. Never delete them by hand.

## Rules

- One script owns one `DST`. Two scripts sharing a `DST` make the second `links::clean` delete the first's links.
- Roots must be absolute. A relative symlink target resolves against `DST`, not the current dir.
- Skill names never contain `/`. `links::sync` reads an argument containing `/` as a new `SRC`, and `links_yaml.py` rejects such a name.
- `links::sync` validates every name before it cleans: a typo is a no-op, not a half-wiped `DST`. That is what makes `_all.sh` safe to run as a test.
- `links::sync_from_yaml` builds one flat `SRC name...` list from the yaml and makes a single `links::sync` call. `links::clean` runs once per call, so a second call would delete the first call's links.
- Both `roots` and `links` keys must be present. An empty `links` map is valid; a missing key is not.
- Rerun = clean then rebuild. `links::clean` deletes only symlinks directly in `DST`; real files and dirs survive — including `link_from_lib.sh` and `link_from_lib.yaml`.
- A script reached through a symlink must use `realpath "$0"` before `cd ..` — plain `cd ..` climbs the symlink's tree.
- `_all.sh` runs each target even if an earlier one fails, then exits non-zero listing the failures. A bad `subscribers.txt` entry is a failure, not a skip.
- `_all.sh` reads the last list line even without a trailing newline. `read` alone fails there, and the entry would be skipped in silence.
- `links::provision` rewrites `link_from_lib.sh` unconditionally and `link_from_lib.yaml` never. That split is the whole point: the script is a constant, the yaml is the project's data. A generated file it did not change keeps its mtime.
- `links::provision` writes files, so it refuses a target that is not a `/.claude/skills` dir inside an existing project. Do not relax those two checks to make a path work — pick the right path.
- `PRIVATE_SKILLS_ROOT` overrides the library path, so moving the library is one env var, not one edit per project.
- `links_yaml.py` needs `python3` with `pyyaml`. Available in WSL/Linux, not guaranteed on Windows — the `.sh` twin already runs there, so this stays a Linux-side dependency.

## The links are machine-local

They are absolute paths into `private_skills`. Committed, they break on every other machine — and they point at a directory named *private*.

`links::gitignore "$DST"` keeps `DST/.gitignore` listing them, and `links::sync_from_yaml` runs it for you:

- it lists the symlinks **present in `DST`**, so the ignore list cannot drift from what `sync` created
- it writes between `# >>> link_from_lib.sh` markers, so rules the project wrote in that same file survive
- it does not touch the file when the content is unchanged
- it writes even when `DST` is not a git work tree — a `.gitignore` there is inert but already correct if the directory is versioned later. Only the `TRACKED` warning needs git

Never untrack a link by hand — rerun the script and the ignore list follows.

`.gitignore` does **not** apply to already-tracked files. If a link was committed before the block existed, `git rm --cached <link>` once per link. The script prints a `TRACKED` warning when it sees one, because nothing else will tell you.
